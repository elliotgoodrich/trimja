# stale_dep_entry

We want to make sure that a `.ninja_deps` entry for a path that is no longer
the output of any build command in the current `build.ninja` is safely
ignored, just like `stale_log_entry` covers for `.ninja_log`.

This happens in practice when `.ninja_deps` is reused across many builds of
changing `build.ninja` files (e.g. cached between CI runs): a path that used
to be generated by a `deps = gcc` build command (and so had its scanned
dependencies logged) can later become a plain source file, or stop existing
altogether, once the build is restructured.

In `bootstrap.ninja`, `foo` is the output of the `compile` rule, which uses
`deps = gcc` and so gets an entry in `.ninja_deps` recording `header.h` as a
dependency. In `build.ninja`, `foo` is only referenced as an input to `out1`
and is no longer produced by any command, so it has no entry in
`nodeToCommand`. Adding the stale `.ninja_deps` entry for `foo` to the graph
must not crash.
