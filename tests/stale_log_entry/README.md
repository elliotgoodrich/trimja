# stale_log_entry

We want to make sure that a `.ninja_log` entry for a path that is no longer
the output of any build command in the current `build.ninja` is safely
ignored.

This happens in practice when `.ninja_log` is reused across many builds of
changing `build.ninja` files (e.g. cached between CI runs): a path that used
to be generated by a build command (and so was logged) can later become a
plain source file, or stop existing altogether, once the build is
restructured.

In `bootstrap.ninja`, `foo` is a build command's output. In `build.ninja`,
`foo` is only referenced as an input to `out1` and is no longer produced by
any command, so it has no entry in `nodeToCommand`. Looking up the stale
`.ninja_log` entry for `foo` against `build.ninja`'s graph must not crash.
